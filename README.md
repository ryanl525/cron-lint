# cronlint

A validating parser and pretty printer for cron expressions.

`crontab -e` tells you "there is an error in crontab file: syntax error" and
nothing else. If you have more than one line, or a schedule generated by
some other tool, you're left guessing which field and which character is
wrong. cronlint parses the expression into a real structure, and when it
rejects something it tells you the exact line and column.

## Install

No package published yet. Clone the repo and use it in place, or copy
`cronlint/` into your project. No third-party dependencies, standard
library only.

## Usage

Parse a single schedule (the usual 5-field minute/hour/day/month/weekday
form, no command):

```python
from cronlint import parse_schedule

fields = parse_schedule("*/15 9-17 * * 1-5")
```

`fields` is a 5-tuple of `Star`, `Value`, `Range`, `Step`, or `ListExpr`
nodes, one per field, that you can inspect or feed to the printer.

### Errors point at the exact character

```python
>>> from cronlint import parse_schedule, CronSyntaxError
>>> try:
...     parse_schedule("*/15 8-99 * * 1-5")
... except CronSyntaxError as exc:
...     print(exc)
line 1, column 8: 99 is out of range for hour (expected 0-23)
  */15 8-99 * * 1-5
         ^
```

### Parsing a whole crontab file

`parse_crontab` walks every line, skips blanks, comments, and `NAME=value`
environment assignments, and parses the rest as `schedule... command`. Line
numbers in errors refer to the original file, so this also works well on a
crontab with dozens of entries:

```python
from cronlint import parse_crontab, CronSyntaxError

text = (
    "# nightly backup\n"
    "0 2 * * * /usr/local/bin/backup.sh\n"
    "*/5 8-25 * * 1-5 /usr/local/bin/check.sh\n"
)

try:
    entries = parse_crontab(text)
except CronSyntaxError as exc:
    print(exc)
# line 3, column 7: 25 is out of range for hour (expected 0-23)
#   */5 8-25 * * 1-5 /usr/local/bin/check.sh
#         ^
```

### Pretty printing

`describe` turns a parsed schedule back into a sentence, which is useful for
showing a non-technical user what a schedule actually means before they
save it:

```python
from cronlint import parse_schedule, describe

print(describe(parse_schedule("30 14 * * *")))
# at 14:30

print(describe(parse_schedule("*/15 9-17 * * 1-5")))
# at every 15 minutes, hours 9 through 17, on Monday through Friday
```

Day-of-month and day-of-week are joined with "or" rather than "and" when
both are restricted, because that's how cron itself evaluates a schedule
like `0 0 13 * FRI` (the 13th of the month, or any Friday — not both at
once). That's a common source of confusion for people writing cron by hand.

### Command line

Installing the package (`pip install -e .`) puts a `cronlint` command on your
PATH for checking crontab files without writing any Python:

```
$ cronlint /etc/crontab /etc/cron.d/*
/etc/crontab: OK (3 entries)
/etc/cron.d/backup: line 2, column 7: 25 is out of range for hour (expected 0-23)
  */5 8-25 * * 1-5 /usr/local/bin/check.sh
        ^
```

It exits 0 if every file given is valid, 1 if any file fails to parse or
can't be read.

## What's supported

- Standard 5-field schedules: minute, hour, day of month, month, day of week
- Wildcards (`*`), ranges (`1-5`), steps (`*/15`, `1-30/5`), and lists
  (`1,15,30`), including combinations like `10-40/5`
- Month names (`JAN`-`DEC`) and weekday names (`SUN`-`SAT`), case-insensitive
- Weekday `7` as an alias for Sunday
- Crontab files with comments and `NAME=value` lines
